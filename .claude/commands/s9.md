# S9 — GitHub Action

Read `docs/SPECIFICATION.md` in full before writing any code. It is the contract. Everything
below extends it and must not contradict it.

## Non-negotiable invariants (already true — keep them true)

- **Fail-closed.** An unknown statement, an unparseable file, an analyzer error, or a panic all
  grade F. No new code path may turn an error, an unknown, or a missing input into a passing
  grade.
- **Determinism.** Identical input produces a byte-identical certificate. No timestamps, no
  UUIDs, no hostnames, no map-iteration order. Every new input must be hashed into `InputDigest`.
- **`internal/domain` imports nothing but stdlib.** Analyzers stay pure functions over a
  changeset: no network, no disk, no git, no database.
- **A rule with no fixture does not exist.**
- Deleting `internal/delivery/` must not break a single engine test.

## Problem

The README's Quickstart is three steps of Go toolchain setup. That is the single biggest install
friction, and it blocks distribution through the Marketplace.

## Build

A composite action at the repo root so `uses:` works directly.

```yaml
- uses: VIKOIT/reversibility-engine@v1
  with:
    path: ./migrations           # default: .
    base: ${{ github.base_ref }} # default: auto-detect from the PR event
    gate: A                      # default: A
    format: markdown             # markdown | json | sarif
    comment: true                # post/update a PR comment
    sarif-upload: false          # upload to code scanning
    config: .reversibility.yml   # optional; wired in S10
```

Requirements:

- `action.yml` (composite) that downloads the released binary for the runner's OS/arch, verifies
  its checksum against the release `checksums.txt`, and caches it. Never `go install` at
  runtime — too slow, and it needs a C toolchain.
- Auto-detect PR context from `GITHUB_EVENT_PATH`; fall back to `--base` on push.
- The comment must **update in place**, matching by a hidden HTML marker in the body, not by
  comment author or position.
- Emit outputs: `grade`, `gate-status`, `findings-count`, `certificate-path`.
- Also emit GitHub annotations (`::error file=…,line=…::`) so findings appear inline on the diff.
- Add `.github/workflows/release.yml` using **goreleaser**: build revctl and revsrv for
  linux/darwin (amd64+arm64) and windows/amd64, publish checksums, attach to the GitHub release,
  and push a `ghcr.io` image. `CGO_ENABLED=1` means cross-compilation needs per-target
  toolchains — configure them explicitly or build each target on its native runner. Do not
  silently disable cgo.
- Update the README Quickstart to the one-step version.

Note: a Docker container action already exists at the repo root from earlier work. Reconcile it
with the composite action rather than leaving two conflicting definitions — and confirm the
direction with the owner if it means removing published behaviour.

## Test

A workflow in this repo that runs the action against `testdata/fixtures` and asserts the expected
grade. The tool must gate itself.

## Standards

- Go 1.22+, `log/slog`, stdlib `net/http`. No new dependencies — ask before adding anything.
- Table-driven tests, fixtures in `testdata/`, `-race` on, `golangci-lint` clean.
- Maintain 85% coverage on `internal/analyzer` and `internal/engine`.
- Update `docs/SPECIFICATION.md` in the same session as the change.
- Conventional commits, one logical change per commit.
- `SchemaVersion` bumps on any certificate field change, with a note in `CHANGELOG.md`.

## Do not

- Do not add a second database engine, a rehearsal runner, a web UI, or a hosted service.
- Do not let context, config, or waivers improve a grade.
- Do not invent classification rules or scoring weights.
- Do not weaken determinism for convenience.

## Finish

Run `make verify`, report what changed, and **STOP**. Do not begin S10 until the owner approves.

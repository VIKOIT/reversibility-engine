# S11 — Production context (the differentiator)

Read `docs/SPECIFICATION.md` in full before writing any code. It is the contract. Everything
below extends it and must not contradict it.

## Non-negotiable invariants (already true — keep them true)

- **Fail-closed.** An unknown statement, an unparseable file, an analyzer error, or a panic all
  grade F. No new code path may turn an error, an unknown, or a missing input into a passing
  grade.
- **Determinism.** Identical input produces a byte-identical certificate. Every new input must be
  hashed into `InputDigest`.
- **`internal/domain` imports nothing but stdlib.** Analyzers stay pure functions over a
  changeset: no network, no disk, no git, no database.
- **A rule with no fixture does not exist.**
- Deleting `internal/delivery/` must not break a single engine test.

## Problem

The engine classifies `ALTER COLUMN TYPE` as `TABLE_REWRITE`. It cannot say whether that is 200
milliseconds or 14 minutes, because it has never seen the database. This session closes the gap
between what the tool claims and what it knows.

## Design constraint — read this before designing anything

The engine does **NOT** connect to a database or a cluster during analysis. A separate command
produces a **snapshot file**; the analyzer reads the file. Three reasons, all binding:

1. CI never needs production credentials. Enterprises will not hand a third-party binary a
   production DSN, and this design means they never have to.
2. Determinism survives. A live query returns different numbers on every run and would destroy the
   byte-identical guarantee the whole product rests on.
3. Analyzers stay pure. `internal/domain` and the analyzers keep their no-network rule intact.

## Build, part 1 — the snapshot command

```bash
revctl snapshot --dsn "$REPLICA_DSN" --out .reversibility/pg.json
revctl snapshot --kube-context prod --out .reversibility/k8s.json
```

- Postgres: `github.com/jackc/pgx/v5`. Kubernetes: `k8s.io/client-go`. These are the only new
  runtime dependencies permitted, and they must be importable ONLY from `internal/snapshot/`. Add
  an architecture test that fails the build if `internal/analyzer/` or `internal/domain/` ever
  imports either.
- Collect **metadata only. Never a single row of user data.** From Postgres: table name,
  `reltuples`, `pg_relation_size`, `pg_total_relation_size`, index name/size/`idx_scan` from
  `pg_stat_user_indexes`, and per-column `null_frac` and `avg_width` from `pg_stats`. From
  Kubernetes: StorageClass names with their `reclaimPolicy`, PVC names with bound status and
  capacity, and workload name/kind/replica counts. Nothing else. Document this list in the
  command's help text — users will ask, and "metadata only" must be verifiable.
- Read-only by construction: open the Postgres connection with
  `default_transaction_read_only=on`; use only GET/LIST verbs against Kubernetes. State the
  minimum required grants in the docs (`pg_monitor` is sufficient).
- Output is canonical JSON: sorted keys, stable ordering, a `SchemaVersion`, a `CollectedAt`
  timestamp, and a `SourceFingerprint` (hash of database identity — never the DSN, which contains
  the password).
- Redact by construction. Add a test that runs the snapshot against a container DB seeded with
  obviously-sensitive values and asserts none appear in the output.

## Build, part 2 — consuming it

```bash
revctl check ./migrations --context .reversibility/pg.json
```

- Multiple `--context` flags allowed; merge by schema type.
- **Enrichment only — never a downgrade.** Context may add detail to a finding and may make a
  grade worse. It may never make a grade better. A large table raises severity; a small table does
  not lower it. Write an explicit property test: for every fixture, grade-with-context is never
  better than grade-without-context.
- A stale snapshot (`CollectedAt` older than 7 days, configurable) produces a warning in the
  certificate. A snapshot whose fingerprint doesn't match a previously seen one for the same
  environment is a config error.
- **A missing context file is not an error.** The tool must work exactly as it does today with no
  snapshot. This is an enhancement, not a requirement.
- Hash every context file into `InputDigest`.

## What enrichment produces

Findings gain optional fields — `RowEstimate`, `SizeBytes`, `EstimatedLockDuration`,
`ContextNote` — and the rendered output becomes concrete:

```
before:  PG006  ALTER COLUMN TYPE — TABLE_REWRITE, COSTLY
after:   PG006  ALTER COLUMN TYPE — full rewrite of 212M rows
                (~48 GB), est. 14 min ACCESS EXCLUSIVE lock
```

Rules that gain context (implement exactly these; do not invent more):

- **PG006/PG007** type changes → row count, table size, estimated rewrite time.
- **PG017** `SET NOT NULL` → if `null_frac > 0`, the migration **will fail**. Say so explicitly;
  this is the highest-value single check in the session.
- **PG014/PG015** `DROP INDEX` → index size and `idx_scan` count. An index with zero scans is
  genuinely cheap to drop; say that too.
- **PG021** FK/CHECK validation → row count and estimated scan time.
- **K8S003** PVC removal → the actual `reclaimPolicy` from the cluster, replacing today's guess.
  If it is `Retain`, this is materially less severe — but per the no-downgrade rule, record the
  fact without improving the grade; report it in `ContextNote` and let a human decide.
- **K8S004** storage decrease → the bound PVC's actual current capacity.

## Estimation honesty

Lock-duration estimates are approximations from row count and size. Label them as estimates
everywhere they appear, document the formula in `docs/ESTIMATES.md`, and never present one as a
guarantee. A number the user learns to distrust is worse than no number.

`docs/PRODUCTION-CONTEXT.md`: what is collected, what is not, required grants, how to run it on a

## Standards

- Go 1.22+, `log/slog`, stdlib `net/http`. No new dependencies beyond `pgx/v5` and `client-go`.
- Table-driven tests, fixtures in `testdata/`, `-race` on, `golangci-lint` clean.
- Maintain 85% coverage on `internal/analyzer` and `internal/engine`.
- Update `docs/SPECIFICATION.md` in the same session as the change.
- Conventional commits, one logical change per commit.
- `SchemaVersion` bumps on any certificate field change, with a note in `CHANGELOG.md`.

## Do not

- Do not add a second database engine, a rehearsal runner, a web UI, or a hosted service.
- Do not let context, config, or waivers improve a grade.
- Do not invent classification rules or scoring weights.
- Do not weaken determinism for convenience.

## Finish

Run `make verify`, report what changed, and **STOP**. Do not begin S12 until the owner approves.
This session is the largest in the plan; if its scope turns out larger still, stop and say so
rather than cutting corners on tests.

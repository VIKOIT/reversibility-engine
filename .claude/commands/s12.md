# S12 — Terraform plan analyzer

Read `docs/SPECIFICATION.md` in full before writing any code. It is the contract. Everything
below extends it and must not contradict it.

## Non-negotiable invariants (already true — keep them true)

- **Fail-closed.** An unknown statement, an unparseable file, an analyzer error, or a panic all
  grade F. No new code path may turn an error, an unknown, or a missing input into a passing
  grade.
- **Determinism.** Identical input produces a byte-identical certificate. Every new input must be
  hashed into `InputDigest`.
- **`internal/domain` imports nothing but stdlib.** Analyzers stay pure functions over a
  changeset: no network, no disk, no git, no database.
- **A rule with no fixture does not exist.** Every new rule ID gets a fixture pair in `testdata/`
  and an entry in the authoritative table in `docs/RULES.md`.
- Deleting `internal/delivery/` must not break a single engine test.

## Problem

Cloud resource deletion is the purest form of irreversibility, and `terraform show -json` is
already structured — no parser risk.

## Build

`internal/analyzer/terraform/`, consuming plan JSON. Classify by the `actions` array in
`resource_changes`, following the same two-axis model as the existing analyzers.

Draft table — **propose it to the owner and wait for approval before implementing.** The owner
owns the classification; you own the code.

| Rule | Change | Reversibility |
| --- | --- | --- |
| TF001 | delete of a stateful resource (RDS, S3, EBS, EFS, DynamoDB, PVC-backed) | IRREVERSIBLE |
| TF002 | `delete` + `create` (forced replacement) of a stateful resource | IRREVERSIBLE |
| TF003 | `prevent_destroy` lifecycle removed in the same plan | IRREVERSIBLE |
| TF004 | deletion protection / backup retention disabled | IRREVERSIBLE |
| TF005 | delete of a stateless resource (security group, IAM role, LB) | COSTLY |
| TF006 | replacement of a stateless resource | COSTLY |
| TF007 | in-place update | REVERSIBLE |
| TF008 | create | REVERSIBLE |
| TF009 | unparseable plan or unrecognized schema version | UNKNOWN |

Requirements:

- Support plan format versions 1.0 and 1.1; an unrecognized version is UNKNOWN, not a best-effort
  guess.
- The provider-agnostic core drives off `actions` and `resource_type`; the stateful/stateless
  decision comes from a **data table** of resource types, not from `if` statements — contributors
  will extend it constantly.
- Never read `terraform.tfstate`. It contains secrets in plaintext. Plan JSON only, and say so in
  the docs.

## Standards

- Go 1.22+, `log/slog`, stdlib `net/http`. No new dependencies — ask before adding anything.
- Table-driven tests, fixtures in `testdata/`, `-race` on, `golangci-lint` clean.
- Maintain 85% coverage on `internal/analyzer` and `internal/engine`.
- Update `docs/SPECIFICATION.md` and `docs/RULES.md` in the same session as the change.
- Conventional commits, one logical change per commit.
- `SchemaVersion` bumps on any certificate field change, with a note in `CHANGELOG.md`.

## Do not

- Do not add a second database engine, a rehearsal runner, a web UI, or a hosted service.
- Do not let context, config, or waivers improve a grade.
- Do not invent classification rules or scoring weights — the table above is a proposal for the
  owner, not a decision you may make.
- Do not weaken determinism for convenience.

## Finish

Run `make verify`, report what changed, and **STOP**.

# S8 — Git ref resolution

Read `docs/SPECIFICATION.md` in full before writing any code. It is the contract: classification
tables, scoring rules, dependency rules, testing requirements. Everything below extends it and
must not contradict it.

## Non-negotiable invariants (already true — keep them true)

- **Fail-closed.** An unknown statement, an unparseable file, an analyzer error, or a panic all
  grade F. No new code path may turn an error, an unknown, or a missing input into a passing
  grade.
- **Determinism.** Identical input produces a byte-identical certificate. No timestamps, no
  UUIDs, no hostnames, no map-iteration order. Every new input must be hashed into `InputDigest`.
- **`internal/domain` imports nothing but stdlib.** Analyzers stay pure functions over a
  changeset: no network, no disk, no git, no database.
- **A rule with no fixture does not exist.** Every new rule ID gets a fixture pair in `testdata/`.
- Deleting `internal/delivery/` must not break a single engine test.

## Problem

The filesystem provider compares two directory paths. Users have two git refs. `--base
origin/main` is documented as unimplemented and it is the first thing anyone hits.

## Build

A `gitProvider` implementing the existing `FileProvider` interface.

```
revctl check --base origin/main
revctl check --base HEAD~1 --head HEAD
revctl check --base v1.2.0 ./migrations
```

Requirements:

- Shell out to `git` — do not add go-git or any git library.
- Resolve refs with `git rev-parse --verify`, list changes with
  `git diff --name-status <base>...<head>` (three-dot: merge base, matching PR semantics).
- Handle all status codes: A, M, D, R (rename), C. A rename is a delete plus an add for analysis
  purposes — the K8s rules need both sides.
- Read blob content with `git show <ref>:<path>`, never from the working tree. The working tree
  may be dirty; the certificate must describe the refs.
- Fail loudly and specifically: not a git repo, ambiguous ref, unknown ref, shallow clone missing
  the base commit (this one is common in CI — say so and name `fetch-depth: 0` in the error
  message).
- `--base` defaults `--head` to `HEAD`.
- Path arguments after `--base` scope the analysis to that subtree.

## Tests

Create real throwaway repos in `t.TempDir()` with `git init`. Cover: added file, modified file,
deleted file, renamed file, subtree scoping, shallow clone failure, dirty working tree ignored.
Skip the suite cleanly if `git` is absent from PATH.

## Standards

- Go 1.22+, `log/slog`, stdlib `net/http`. No new dependencies — ask before adding anything.
- Table-driven tests, fixtures in `testdata/`, `-race` on, `golangci-lint` clean.
- Maintain 85% coverage on `internal/analyzer` and `internal/engine`.
- Update `docs/SPECIFICATION.md` in the same session as the change — never in a later one.
- Conventional commits, one logical change per commit.
- `SchemaVersion` bumps on any certificate field change, with a note in `CHANGELOG.md`.

## Do not

- Do not add MySQL, MongoDB, or any second database engine.
- Do not build the live rollback rehearsal runner.
- Do not build a web UI, dashboard, or hosted service.
- Do not let context, config, or waivers improve a grade.
- Do not invent classification rules or scoring weights. Propose them to the owner.
- Do not weaken determinism for convenience.

## Finish

Run `make verify`, report what changed, and **STOP**. Do not begin S9 until the owner approves.
If the scope turns out larger than expected, stop and say so rather than cutting corners on tests.
